# C. ゲーム本体と画面の境界

正本のコード: `RFSim/Simulation.swift`・`RFRules/SimSystem.swift`・`RFPresent/`。

## 1. 流れ
```
画面(SwiftUI) ──Command──▶ GameHost(actor) ──▶ Simulation.apply / advance ──▶ 各システム(固定ステップ)
     ▲                           │                                              │
     └──────── Frame ◀── FrameBuilder(認識の層を通す) ◀── StepReport(出来事・変化の印・断った理由)
```
- 画面は意図(`Command`)を送るだけ。世界状態を直接書き換えない。
- 本体(`Simulation`)は値型で状態を持たない。世界状態は `GameHost` が 1 つ持ち、`inout` で渡す。
- 結果は `StepReport`: 出た出来事(`DomainEvent`)・変わった所の印(`ChangeSet`)・断った理由(`Rejection`。画面は足元カードに 1 行。ダイアログは出さない)・進めたステップ数・警告。
- 画面に出す文字は `Frame`(すべて認識の層を通した後の文字列)だけから取る。

## 2. システムの順番(1 ステップ)
時間 → 人(移動・配属)→ 探索 → 生産 → 運搬 → 拠点 → 研究 → 力 → 戦闘 → 生存 → 発明 → 出来事 → 失敗。
1 ステップの中で、各システムの `step` を順に呼び、出た出来事を全システムの `react` に配る(反応が出来事を出せば、最大 16 周まで繰り返す)。効果から出たコマンド(`ctx.queue`)もこの間に処理する。
コマンドはステップの境目で処理する(`apply`)。夜作業の行為は「かかる時間」を返し、本体がその分のステップを続けて進める。

## 3. 時間 — 固定ステップ・リアルタイムの昼・夜の一括・一時停止
- 1 ステップ = ゲーム 15 秒(`SimStep.gameSeconds`)。昼 180 実秒 = 8 ゲーム時間なら、実時間 1 秒あたり約 10.7 ステップ。
- **昼**: 画面のタイマーが `GameHost.tick(realSeconds:)` を呼ぶ。本体は実時間をステップ数に直す。端数は `clock.realCarry` に**整数で**繰り越す(単位: 実マイクロ秒 × 昼のゲーム秒。1 ステップ = 昼の実秒 × 10⁶ × 15)。だから刻み(1/60 秒でも 0.37 秒でも)によらず、日没の時点の世界が一致する(テスト `testRealtimeIsIndependentOfFrameRate`)。
- **日没**: 昼のゲーム時間が尽きると phase = dusk。時計は止まる(`advance` は何もしない)。帯で「夜作業」「寝る」を選ぶ(画面は止めない。全画面のシートを出さない)。
- **夜作業**: phase = nightWork。行為(試作・会話・手仕事・研究)が `CommandResult.accepted(time:)` で時間を返し、その分だけ進む。
- **寝る**: 夜明けまでのステップを一括で進める(同じ `step` 関数。夜の生産・消費・脅威も同じ規則で起きる)。
- **一時停止・アプリが非アクティブ**: 画面が `tick` を呼ばないだけ。本体は壁時計を読まない(閉じている間は進まない)。
- **止める決断**: `PendingDecision.blocking` が true の間だけ、`advance` は進まない(コンテンツが決断ごとに指定。既定は止めない)。

## 4. SwiftUI からの観測と 60fps
- `GameHost` は actor。シミュレーションは主スレッドの外で動き、主スレッドには `Frame`(値)だけが渡る。主スレッド側の `@Observable` なストアは Frame の項目ごとにプロパティを分けて持ち、変わった項目だけを差し替える(SwiftUI は差し替わった項目を読むビューだけ描き直す)。
- **地図**: 16×16 の区画ごとの版(`MapView.chunkRevisions`)。変わった区画だけを描き直す(区画の中身は `FrameBuilder.tile` で引く。区画の絵は画面側でキャッシュする)。知っている事実が変わったとき(`ChangeSet.perception`)は全区画の版を上げる(遡る書き換え)。
- **動く物**: `ActorSprite` は前のマス・次のマス・進み(0〜1000)を持つ。シミュレーションのステップ(約 10 回/秒)と描画のフレーム(60 回/秒)を切り離し、画面が `TimelineView` などで補間して滑らかに描く。
- **文字**: 名前・ラベルは Frame を作るときに一度だけ引く。事実が変わらない限り同じ文字列。
- 地図の描画は SwiftUI の `Canvas`(または固定サイズの格子)で、1 マス = 1 文字を固定の正方形の枠の中央に描く(order.md §5.5)。

## 5. 工程表(設計画面の部品)を任意の表で開く(REQ-S8)
設計画面の縦一列の工程表は、ライン札専用にしない。`ProcessSheet`(出所 = ライン札 / 試作 / コンテンツの記録 `SheetDef`、題、行(見出しと注記)、結果)を同じ部品で描く。コンテンツの記録は条件(`SheetDef.when`)が成り立つまで開けない。行ごとの条件もある。

## 6. 中断と再開
- 画面の途中の状態(置くモードの照準・設計画面の下書き)は画面側の状態で、本体の世界状態には入れない。アプリを閉じるときに画面側で保存する(D の resume に添える)。
- 本体の途中の状態(押し続ける手作業・歩いている途中・場面の何行目)は世界状態にあるので、保存から戻れば続きから。

## 7. 走行の記録と再現
`GameHost.replayLog` に (ステップ番号, コマンド) を残す。seed とこの列で走行を再現できる(不具合の再現・ボットのテスト)。
