# 美術の方針(ビジュアル C: 文字グラフィックス+要所の絵)

この文書は公開してよい内容だけを書く。物語の中身・絵の題材の具体は非公開のコンテンツ側に置く。

## 0. 一言で

- **遊びの面は文字で描く。** 地図・品物・生産ラインは、等幅の文字と色と小さな動きで見せる(原作 `docs/design/systems/visual-design.md` が正本)。
- **絵は感情の要所にだけ置く。** ただし、いま入っている絵はタイトルの 1 枚だけで、それも**仮**とする(オーナーが見るまで)。アプリのアイコンは A2R_1 を本採用とする(オーナーの決め)。
- **人物の絵は、チームでは作らず、どこからも入れない。** 立ち絵・キーパーソン・山場の人物の絵をどう用意するか(画像生成で詰める・人に依頼する・素材を買う)は、オーナーが決める(いま試作と検討の最中)。買った素材は、AI の学習にも、画像から画像を作る生成の元にも使わない。それまで人物の枠は空けておき、名前と台詞の文字だけで成り立たせる(§4.5)。
- **品物には絵を付けない。** 絵は、文字より多くのことを語ってしまうから。
- **画面の部品は墨の地に生成りの文字、差し色は錆の 1 色。** 標準のシート・アラート・ボタンの見た目は使わない。

## 1. 色

### 1.1 遊びの面(地図)

原作どおり、黒の地に色つきの文字。値は `ReForgeCore/Sources/RFPresent/Palette.swift`(`TilePalette`)が正本。

| 面 | 文字 | 色(RGB) |
|---|---|---|
| 地面 | `. ,` | 土色 (110,95,75)〜(125,110,85) |
| 草 | `\| / \ ψ † ŧ` など | 緑 (60,110,60)〜(110,150,60) |
| 森 | `⍋` | 暗緑 (40,100,45)〜(70,135,65) |
| 水辺 | `. ∙` | 水色 (70,110,180)/(130,170,220)、地は青 (30,50,90) |
| 岩 | `ﾛ .` | 灰 (100,95,88)〜(120,115,105) |
| 鉱脈 | `晶` | 系統の色(1.3) |

人や物の印: 敵は暗い赤 (170,55,55)、止まった物はくすんだ赤 (150,72,72)。鮮やかな赤は使わない(§1.2)。

夜は視界の中を 0.75 倍、覚えているだけの所を 0.42 倍に暗くする。灯りの届かない所には、物と生き物を描かない(VIS-08)。

### 1.2 画面の部品(`ReForge/Sources/Theme/InkColor.swift`)

| 名前 | 用途 | 値(sRGB) |
|---|---|---|
| `field` | 地図の下の地 | #000000 |
| `ground` | 画面の地・帯・タブ | #11131A |
| `panel` | パネル・札の地 | #1B1E27 |
| `raised` | 押している・選んでいる行 | #2A2E3A |
| `rule` | 罫線(1pt) | #414553 |
| `text` | 本文(生成り) | #E6DFD0 |
| `textDim` | 補助・ラベル | #999790 |
| `textFaint` | 押せない | #666666 |
| `accent` | 主ボタンの地・開いているタブの線(錆) | #B86B48 |
| `onAccent` | 錆の上の文字 | #11131A |
| `notice` | 断られた理由の 1 行 | #F5B375 |
| `alert` | 危ない・取り返しがつかない(ふつうの赤) | #D7875F |
| `good` | 動いている・できた | #96C890 |
| `night` / `dusk` | 夜 / 夕方・昼の残り | #7584C8 / #E6B864 |
| `reserved` | 鮮やかな赤。予約された特別な用途(使う場所はまだ作らない) | #F0283C |

決まり:

- **赤は 2 種類。鮮やかな赤は予約された特別な用途。**
- 錆(`accent`)は 1 画面に 1 か所だけ。主の行為と、いま選んでいる物にだけ使う。
- 意味の色(`notice` `alert` `good` `night` `dusk`)は文字にだけ使い、面には塗らない。
- 遊びの面の色を部品に流用しない。逆も同じ。部品は遊びの面より常に静かにする。

### 1.3 品物の名前の色(純度と、知っている系統)

`ReForgeCore/Sources/RFPresent/ItemColor.swift` が正本。

- **明るさ = 純度**: 0.3 + 0.6 × (純度 − 20%) / 80%。99% を超えたら、ナイン数ぶん明るくする。純度が見えていないときは中くらいの明るさにする。
- **鮮やかさ = 鮮やかさの段(0〜5)**: 彩度 0.10 / 0.25 / 0.40 / 0.60 / 0.75 / 0.85。
- **色相 = 系統**: 無彩 / 暖(30°) / 緑(90°) / 青(200°) / 紫(280°)。
- **動き**: 光沢(暖の系統で段 2 以上。4 秒に 1 回、0.3 秒で横切る)/ 明滅(段 3 以上)/ 色相のゆらぎ(紫の段 5)/ きらめき(見え方に `sparkle` があるとき)。日常品と有機物は光らせない。

**色の入力は真実の素材ではない(VIS-01)。** 系統と段は、認識の層の見え方(`Variant.tint`)に書く。`Perceiver.tint(of:)` が、いまの見え方の系統を返す。見え方に系統が無ければ中立(ほぼ無彩・動きなし)にする。正体の分からない物は中立の色で出す。
事実を知って見え方が変わると、色も同じ時に変わる。手がかりとして公平な範囲で小さな動きを先に付けることはできる。ただし、それは見え方の側で書き、真実の側から計算しない。

### 1.4 絵の色

- 1 枚に 2〜4 色。淡く、コントラストを低くする。
- 黒は使わない。いちばん暗い色は沈んだ灰藍にする。
- 差し色(火など)は 1 枚の中で 1 か所にとどめる。鮮やかな赤は使わない(§1.2)。
- 画面の部品の色(1.2)と絵の色は揃えない。絵は絵の中で完結させる。

## 2. 文字組み(`InkFont`)

書体は言語ごとに 1 つ。日本語・英語は同梱の BIZ UDGothic(地図と同じ書体)、簡体字は PingFang SC、繁体字は PingFang TC、韓国語は Apple SD Gothic Neo(iOS の標準の書体なので同梱しない。BIZ UDGothic にはハングルと簡体字の字形が無い)。選ぶ入口は `InkFont.setLanguage` の 1 か所。地図の 1 マス 1 文字は言語によらず BIZ UDGothic。大きさは 5 段で、Dynamic Type に追従する。

| 名前 | 大きさ | 用途 |
|---|---|---|
| `caption` | 12pt | 注記・長押しの説明・バージョン |
| `small` | 14pt | 帯・一覧の補助・小見出し |
| `body` | 15pt | 本文・ボタン・一覧の行 |
| `heading` | 20pt 太字・字間 +1.5 | パネルと札の見出し |
| `display` | 40pt 太字・字間 +4 | タイトルの文字だけ |

- 行間は本文の 1.5 倍を目安にする(`bodyLineSpacing` = 7pt)。
- 数字は `monospacedDigit()` で桁をそろえる。
- 文言は補間しないリテラルで書く。数や名前が入る文は本体で組み、`Text(verbatim:)` で出す(`tools/gen-xcstrings.py`)。

## 3. 画面の部品の決まり(`ReForge/Sources/Theme/`)

| 部品 | 使い方 | 決まり |
|---|---|---|
| `.buttonStyle(.ink(.primary / .secondary / .quiet))` | すべてのボタン | primary は 1 画面に 1 つまで。並んだ選択肢は同じ重さ(secondary)にする |
| `InkHoldButton(label:hint:action:)` | 取り返しのつかない行為(記録を消す・最初から) | **確認のダイアログの代わり。** 押し続けると帯が満ち、満ちたときだけ実行する。説明は hint に 1 行で書く |
| `InkPanel(title:) { … }` | タブの中身の土台 | 見出しは 1 つ。中身は自分でスクロールする |
| `InkSection(title:) { … }` | パネルの中のまとまり | 小見出し+罫線 |
| `InkRow(glyph:glyphColor:title:detail:value:selected:)` | 一覧の 1 行 | 高さ 44 以上。左の記号は遊びの面の色(`Color(rgb:)`)にする。押せる行は `.buttonStyle(.inkRow)` |
| `InkBand(edge:) { … }` | 画面の上下に張りつく帯 | 地は `ground`、境に罫線 |
| `InkPlate(title:) { … }` | 地図の上に重ねる中央の札(ゲームオーバーなど) | 背景を沈め、札は幅 360 まで |
| `.inkCard(isPresented:title:) { … }` | 下からの札(設定など) | **iOS の `.sheet` は使わない。** 上に残った画面は暗くせず、押せるまま。時計も止めない。引き下げて閉じる操作は無い。閉じるのは札の「閉じる」か、開いた元のボタン。次の段へ進むときは、札を重ねずに中身を差し替える |

右上の 52×52pt(`InkMetric.settingsReserve`)は、窓に 1 つだけ置く設定のボタン(歯車。暗い半透明の丸の上)の場所として、上の帯・頁の見出し・下からの札の見出しで空けておく。

使わないもの: `.sheet` `.fullScreenCover` `.alert` `.confirmationDialog` `.bordered` `.borderedProminent` `Form` `NavigationStack` の見た目。
モジュールの画面も、地図を止める重ね画面にしない。止めない下のパネルにする。温度の棒と状態の色は原作を引き継ぐ(VIS-07)。

## 4. 絵の決まり

人物を含まない絵(タイトルの背景など)に使う基準。人物の絵の用意の仕方は §0 のとおりオーナーが決める。人が描いた素材を使う場合も、この線と色の感覚に合わせる。

基準はオーナーの判断(「AI っぽさ」の見分け)に従う。AI っぽく見える原因は、**完璧すぎる輪郭**と**色の多さ**の 2 つ。

### 4.1 線

- 細く、柔らかく、淡い色(黒は使わない)。
- コントラストを低くして、色に半分溶けるような繊細な線にする。
- くっきりした完璧な輪郭にしない。太いラフ線やカートゥーン線にもしない。

### 4.2 色

- 色数を絞る(1 枚に 2〜4 色)。淡く、コントラストを低くする。
- 塗りは平らにし、光は一方向から平らに当てる。

### 4.3 やってはいけないこと

- リソ・版画・エディトリアル・カートゥーンの画風。
- グラデーションの陰影、リムライト、頬や鼻の光るハイライト、多方向の髪のハイライト、遊び毛。
- 読み取れない装飾で埋めた背景。背景は無地か、ごく単純にする。
- 全体を同じ密度で描き込むこと。描き込むのは顔だけにし、服は平らに省く。
- 魅力を盛った「平均的な美形」。個性は、磨きではなく**その人だけの造形**(少し誇張した、平均から外れた顔立ち)で出す。
- 広告のような笑顔、カメラ目線、決めポーズ。表情は日常の中間にする。
- **全員に 1 つの絵柄を貼ること。** 共有するのは線と色の感覚だけにする。構図・ムード・顔立ちは 1 枚ずつ描き分ける。

### 4.4 何を描かないか(真実を先に見せない)

- **絵とアイコンには、訳が要る文字を描かない(ロゴは可)。** タイトルの題字はアプリが重ねる。アイコン A2R_1 の「Re:」はロゴで、アプリ名はどの言語でも Re:Forge なので可。
- **品物は描かない。** 山場の絵も、人と光(炉の明かりに照らされた顔など)だけを描く。品物は文字のままにする(VIS-04)。
- 人物は全員同じ規則で描く。絵の見え方は事実で差し替える(中身は非公開)。
- 山場の絵も、人物を含むものは作らない。人物を含まない山場の絵を作るかどうかは、タイトルの絵へのオーナーの判断を待つ。

### 4.5 人物の枠(絵が無いときの形)

- 人物の絵を置く場所は、絵が無いときに**場所ごと消える**。空の枠・シルエット・仮の絵・頭文字の丸などは置かない(`ArtView` は絵が無ければ何も描かず、場所も取らない)。
- 会話と登場は、名前(太字の 1 行)と台詞の文字だけで成り立つ組み方を正とする。絵はあとから足せる上乗せにする。
- 絵が入ったときも、文字の組み方は変えない(絵は台詞の上か横に足すだけ)。

### 4.6 立ち絵の形と見せ方(絵が用意できたとき)

人物の絵をどう用意するかはオーナーが決める。ここでは、用意できたときの受け皿だけを決める。

- **水準の目安**: オーナーが買ってよいと判断した市販の立ち絵(手元の参考。リポジトリには入れない)。アニメ調、平らな塗りに筆の跡が少し残る陰影、自然な主線、くすんだ落ち着いた色。
- 主人公の見た目は、女性的な特徴がやや強めの中性。
- **素材の形**: 縦長の全身、幅:高さ = 11:25(例 1100×2500)。透過の PNG を基本にする。白い背景の素材は、透過にしてから入れる。表情の差分は、最初は 1 枚(通常)だけ。
- **置き場**: 物語の層(`content/private/art/<ArtID>.png` → `art.sealed`)。ID は `ArtID` の人物の分で、中立の番号にする。公開リポジトリには入れない。
- **見せ方**:

| 場所 | 出し方 |
|---|---|
| 場面(下からの札) | 札の横に、胸から上を切り出して出す(上から約 45%)。台詞の組み方は変えない |
| 仲間のタブの人物の頁 | 全身を出す(11:25 のまま、縮めるだけ) |
| 地図 | 出さない(地図は文字のまま) |

- **絵が無いとき**: 枠ごと出さない。名前と台詞の文字だけで成り立つ形のまま(§4.5)。
- 切り出しは画面の側で行う(素材は全身の 1 枚だけを持つ)。

- **発注のときのメモ**: 眼鏡をかけた人物が 2 人いる。絵を頼むときは、2 人の眼鏡の形や印象で見分けがつくように指示を書く。

### 4.7 いまの絵の扱い

| 絵 | 状態 |
|---|---|
| タイトルの背景(`ReForge/Resources/Art/title-art.png`) | 仮。オーナーが見るまで |
| アプリのアイコン(`ReForge/Resources/Assets.xcassets/AppIcon.appiconset`) | 本採用(A2R_1。オーナーの決め)。新しい案は作らない |
| 人物の絵 | 無し。用意の仕方はオーナーが決める(チームでは作らない) |

## 5. 文字グラフィックスと絵の境界

| 面 | 文字で描く | 絵で描く |
|---|---|---|
| 地図・地形・構造物・人の位置 | ○(1 マス = 1 文字) | — |
| 品物・素材・在庫・図鑑 | ○(名前の色と動き) | 描かない |
| 生産ライン・設計の工程表・ノート | ○ | — |
| 会話・出来事 | ○(短い文) | 要所の 1 枚だけ |
| キーパーソンの登場・山場 | ○(名前と台詞だけで成り立たせる) | 人物の絵はオーナーの判断待ち(チームでは作らない) |
| タイトル | 題の文字 | ○(背景の 1 枚。仮) |

- 絵は画面の部品の中に置く。地図の上に直接は置かない。
- 絵が読めないとき(封が開かないときなど)は、文字だけで成り立つようにする。絵は飾りではなく、無くても遊べる層にする。

## 6. 絵の置き場

| 種類 | 置き場 | 読み込み |
|---|---|---|
| 公開してよい絵(タイトル。仮) | `ReForge/Resources/Art/` | `UIImage(named:)` |
| 立ち絵・山場の絵(いまは無し) | 非公開の `content/private/art/<ArtID>.png`(公開リポジトリには入れない) | `content/art.sealed` に封をして束に入れる。`ContentLoader.loadBundledArt` で読む。アプリ側は `ArtProvider` で包み、開けなければ絵なしにする |

`ArtID` は中立の番号にする(意味の分かる名前を付けない)。どの山場の絵かの対応は、非公開のコンテンツに書く。
