# D. 保存の形式・セーブ地点・巻き戻し

正本のコード: `RFSave/SaveCodec.swift`・`RFFailure/Failure.swift`。

## 1. 形式
- 1 ファイル = `SaveEnvelope`(JSON・キーは昇順): `format`("reforge.save")・`schemaVersion`(世界状態の形の版)・`content`(遊んでいたコンテンツの層の id と版)・`slot`・`world`(`WorldState` 丸ごと)。
- 世界状態は ID と整数だけ(B §1)。名前・文章は入らないので、コンテンツの文を直しても保存は壊れない。
- 本体はファイルに触らない。置き場はアプリが `SaveStorage`(書く・読む・消す・一覧)を FileManager で実装する(テストは辞書)。書くときは一時ファイル → 置き換え(途中で落ちても前の保存が残る)。
- b7 の保存(`SaveFile` 版 1)は読まない(旧版の互換は除外候補。b7 の利用者はオーナーだけ)。

## 2. 保存の場所(スロット)
| スロット | いつ書く | 何に使う |
|---|---|---|
| `resume` | アプリが背面に回る・閉じる・日没・夜明け・決断を出したとき(画面側が呼ぶ) | 「つづきから」。時計は止めた状態で戻す |
| `dawn(day)` | 夜明けごと(自動)。直近 3 日ぶん残す(`SavePolicy.keepDawns`) | 巻き戻しの戻り先(最新)と「セーブ地点からロード」 |
| `manual(index)` | プレイヤーが拠点の画面から(確認は出さない。上書きは戻せないので 3 枠) | 「セーブ地点からロード」 |

画面の途中の状態(置くモードの照準・設計画面の下書き)は世界状態に入れない。`resume` と同じ時に画面側の小さな JSON として別に書く(読めなくても遊べる)。

## 3. ゲームオーバーの 4 択と、巻き戻しの持ち越し
失敗はコンテンツの失敗の規則(`FailureRuleDef`。期限も値で判定)が成り立ったとき(`run.outcome = .failed`)。画面は 4 つを同じ重さで並べる。

| 選択 | 作り方 |
|---|---|
| 最初から | `WorldFactory.newWorld(seed: 新しい seed)`。何も持ち越さない |
| 記憶を持って巻き戻す | `MemoryCarry.rewind(failed:, dawn: 最新の dawn, content:)`。最新の夜明けがすぐ失敗に落ちる場合のため、直近 3 日の夜明けから選べる |
| 失って続ける | 失敗した世界に、コンテンツの `RewindDef.lossEffects`(誰かが去る・物を失う…)を適用し、失敗の原因の値を戻して続ける。失ったものは来歴に残る |
| セーブ地点からロード | `dawn` か `manual` を読む。持ち越しなし |

記憶を持って巻き戻すときの分け方(MECH-04・REQ-S6):

| 戻す(夜明けのまま) | 残す(失敗した世界から写す) |
|---|---|
| 在庫・ライン・置いた物・建造物・運搬 | 知った事実(コンテンツの `FactDef.scope` が memory のもの。timeline のものは消える) |
| 仲間の生死・位置・体・配属 | 地図の既知・見つけた POI と鉱脈・図鑑の影 |
| 時計・数値・出来事の進み・範囲の効果 | 実験ノート(試作・所見・出典つきの書き留め・聞いたヒント) |
| 研究の進み・解禁 | 関係の点とランク(割合は `RewindDef.relationPermille`、既定は全部) |
| 来歴(夜明けまで) | 巻き戻しをまたぐ記憶(`MemoryRecord.persistsAcrossRewind`) |
| | 前の周回の「覚えておく」記録(`RewindDef.memorableTags` の印の付いた来歴 → `run.pastLives`) |

- 周回の番号(`run.index`)を 1 つ増やす。実体の ID と来歴の番号は失敗した世界の続きから振る(前の周回の記録と番号が重ならない)。
- 仲間の「前にもこうなった気がする」は、`pastLives` の記録を条件(`Condition.runAtLeast`・来歴の問い合わせ `currentRunOnly: false`)で引く一言(`LineDef`)で出す。

## 4. 版と移行
- 世界状態の形を変えたら、`SaveCodec.schemaVersion` を 1 上げ、`SaveCodec.migrations` に「前の版の JSON の木(`Value`)を次の版の木に書き換える」移行を 1 つ足す。古い struct を残さなくてよい。
- 読むときは版を 1 つずつ上げる。移行が無い版・新しすぎる版は読まない(壊れた状態で始めない。画面は「この保存は読めない」と 1 行出し、他のスロットを勧める)。
- コンテンツの ID を付け替えたら、コンテンツ側に付け替えの表を置き、読み込み後に世界状態の ID を写し替える(U3・U12 で形を決める。R1 のリリースまでは不要)。
- 最初のリリース(R1 を外に出す)までは版 1 のまま形を変えてよい。リリース後は必ず移行を足す。

## 5. 受け入れテスト(U12)
- 封筒の往復(書いて読んで同じ)。移行の連鎖・新しすぎる版・保存でないファイル。
- 巻き戻しの持ち越し(上の表の各行)。番号が重ならない。timeline の事実は消える。
- 4 択のそれぞれで、続けられる世界になる(`run.isActive`)。
- 中断(TEST-R1-08): 置くモード・試作の途中・会話の途中で `resume` を書き、読んで続きから(時計は止まっていた)。

## 6. U12 の実装で決まったこと(b59cac6)
- 封筒に `summary`(seed・日・相・周回・巻き戻し回数・進行中か)。一覧の表示と「同じ走行の夜明けか」の判定に使う。
- 画面の途中の状態は `SaveSlot.screen`(ファイル `resume-ui.json`)に生の Data で置く。
- 保存の JSON は自前の正準の書き出し(`CanonicalJSON`。Set と非文字列キーの辞書をソート、キーは UTF-8 順)でバイト列を固定する。固定の JSON は `Tests/RFSaveTests/Fixtures/save-v1.json`。リリース前は形が変わるとテストを飛ばし、作り直し方(`REFORGE_UPDATE_SAVE_FIXTURES=1`)を出す。リリース後は失敗にする。
- 失って続ける: `RewindDef.lossEffects` があればそれだけ。無ければ既定(関係の点が最も低い一員 1 人が去る・拠点の蓄えの唯一品でない物の 500‰ を失う)と、成り立っていた失敗の規則の `onContinue`。適用しても失敗の規則が成り立つなら選べない。
- 巻き戻しの `pastLives` には、印の付いた記録と失敗の記録に加えて、持ち越した事実・ノート・仲間の記憶が指す記録の写しを残す(`RunState.pastRecord` で引ける)。夜明けの一員(ノア以外)に `RewindDef.dejaVuMemory` の記憶を付ける。
- 保存の書き換えは `Recovery.perform` の中: 最初から = 夜明けと続きを消す(手動は残す)/ 巻き戻し = その夜明けを巻き戻した世界で上書きし、先の夜明けを消す / ロード = 先の夜明けを消す。
- 画面へのつなぎ(統合担当が GameHost に入れる): `SaveBook.autosaveDawn`(出来事に dawn)・`writeResume`(背面に回る時)・`Recovery.choices / perform` → `GameHost.replace`。
