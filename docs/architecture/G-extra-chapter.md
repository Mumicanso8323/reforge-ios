# G. 追加の章(有料の続き)の作り

状態: 設計(実装は本編がそろってから)。オーナーの決定「物語の続きを有料の追加の章で出す」(2026-10-02)に合わせる。追加の章の範囲と、場面の中身にかかわる決まりは、非公開の reforge-plan の側(結末と続きの文書)にある。
公開リポジトリなので、物語の語も、場面の中身が推し量れる言い方も書かない。呼び名は「本編」と「追加の章」(コードでは `chapter2`)と、本編の中の 2 つの時点「本編の途中の節目」(`main.mark`)と「本編の最後の日」(`main.final`)だけにする。

## 0. 決めたこと(要約)
| ID | 問い | 決め |
|---|---|---|
| DEC-G1 | 買う仕組み | StoreKit 2 の**非消耗型**。品の ID は `reforge.<名前>`(`reforge.remove_ads`・`reforge.chapter2`。次は `reforge.chapter3`)。広告消しと同じ `StoreService` に乗せる |
| DEC-G2 | 買ったことの確かめ | 起動時と `Transaction.updates` で `Transaction.currentEntitlements` を読み、**検証済み**(`.verified`)で取り消されていない取引だけを権利とする。最後に確かめた権利を端末に覚え、ストアに届かないときはそれを使う(オフラインで遊べる) |
| DEC-G3 | 復元 | 設定の購入の所に「購入を復元」を置く(`AppStore.sync()` の後に権利を読み直す)。起動時の自動の確かめでも、同じ Apple ID なら自然に戻る |
| DEC-G4 | 家族共有 | 既定の案: **有効にする**(App Store Connect の品の設定)。家族共有で得た権利(`ownershipType == .familyShared`)も、買った権利と同じに扱う。**オーナーが決める**(§6) |
| DEC-G5 | 広告 | 既定の案: 広告を出さない条件は「`remove_ads` か `chapter2` を持っている」。広告消しは単独の品として残す。**お金の決まりなので、オーナーが決める**(§6) |
| DEC-G6 | 本文の束 | 追加の章は**本編と別の束**: 言語に依らない部分 `chapter2.sealed` と、言語ごとの `chapter2-text-<言語>.sealed`(本編の L10n DEC-L5 と同じ分け方) |
| DEC-G7 | 鍵 | 本編と追加の章で**別の鍵**(ビルドごとの使い捨て)。どちらもアプリの本体に埋める(オフラインで開くため) |
| DEC-G8 | 同梱か後から落とすか | **同梱する**。買った後、ネットが無くても始められる(完全オフラインの決まり)。Background Assets・On-Demand Resources は使わない |
| DEC-G9 | 買っていない人の束 | 束は ipa の中にあるが、**開かない**(読み込みで鍵を使わない。メモリにも展開しない) |
| DEC-G10 | 本体の重ね方 | 追加の章は、公開 → 非公開 の上に重ねる**3 つ目の層**。ただし重ねるのは追加の章を遊んでいる間だけ(「遊ぶ場」ごとに `ContentDB` を作る。§3.1) |
| DEC-G11 | 本編からのつなぎ | 本編の 2 つの時点(途中の節目・最後の日)を、自動の**節目の枠**(`SaveSlot.milestone`)に残す。追加の章は「最後の日」の世界から始める。追加の章へつながらない終わり方をした人は、「途中の節目」から本編で遊び直す(非公開の側の既定) |

## 1. 買う仕組み(DEC-G1〜G5)
### 1.1 品
| 品の ID | 種類 | 表の名前(ストアの原稿 `store/iap/<ID>/<地域>.json`。L-14) | 権利 |
|---|---|---|---|
| `reforge.remove_ads` | 非消耗型 | 広告を消す | 広告を出さない |
| `reforge.chapter2` | 非消耗型 | 追加の章 | 追加の章を遊べる(広告の扱いは DEC-G5) |

- 値段はオーナーが決める。アプリは値段を持たず、StoreKit の表示の文字列をそのまま出す(L10n §12.2)。
- `ProductID` に `chapter2` を足し、`StoreService.productIds` に並べる。`store/iap/reforge.chapter2/` を 5 言語で足す(`check-store-metadata.py` が品ごとの 5 言語を確かめる)。

### 1.2 権利の確かめ(DEC-G2)
- 起動時: `Transaction.currentEntitlements` を全部読み、`.verified` で `revocationDate == nil` の取引の品の ID の集まりを権利とする。
- 起動中: `Transaction.updates` を待ち受け、来た取引を `finish()` して、権利を読み直す(家族共有の追加・払い戻しの取り消しもここで来る)。
- 端末の覚え: 最後に確かめた権利の集まりを、アプリの設定の置き場(`UserDefaults`。今の「広告を消した印」と同じ所)に書く。StoreKit が読めない(機内など)ときはこれを使う。払い戻しで消えた権利は、次にストアに届いたときに消える。
- **権利を保存(`SaveEnvelope`)には入れない**。保存はどの端末でも同じに読めるものにし、権利は端末と Apple ID の側に置く。

### 1.3 画面
- 追加の章の案内は、タイトルの一覧の 1 行(本編をクリアした人だけ。§4.2)と、設定の購入の所だけに置く。本編の終わりの場面・クレジット・その後の 1 枚には、購入・値段・案内を出さない(非公開の側の決まり。テストは §4.1)。
- 「購入を復元」は設定の購入の所に 1 つ(非消耗型の決まり)。

## 2. 封をした本文の出し分け(DEC-G6〜G9)
### 2.1 束
| 束 | 中身 | 鍵 |
|---|---|---|
| `private.sealed` / `text-<言語>.sealed` | 本編の非公開の層(L-04 の形) | 本編の鍵 |
| `chapter2.sealed` / `chapter2-text-<言語>.sealed` | 追加の章の層(言語に依らない JSON と、言語ごとの文言) | 追加の章の鍵 |

- 形は今の `RFS1`(合図 + nonce + AES-256-GCM)のまま。束ごとに nonce を変える。
- `rf-seal` に「層の名前」を渡せるようにする(本編 = `private`、追加の章 = `chapter2`)。`stage.sh` が両方を作る。
- CI の確かめに足す: ipa の中に、追加の章の平文の JSON・文言が無い(今の「非公開の絵の指紋が ipa に無い」と同じ作り)。

### 2.2 どこまで守るか
- 守れるもの: ipa を開いて眺める・ファイルを検索する・ストアの外で配られた ipa を覗く、の程度で、本文と答えが見えない(ネタバレの防止)。買っていない人の端末でも、束は開かれず、メモリにも展開されない。
- 守れないもの: アプリの本体を解析して鍵を取り出す人。鍵は、オフラインで開くためにアプリに入っている。これは本編の束と同じ水準で、DRM ではない。
- この水準を選ぶ理由: 完全オフラインの決まりを守ると、鍵をサーバから受け取る形が取れない。強くしたくなったら、そのときに「買った後に鍵をサーバから受け取って端末の Keychain に置く」形へ替えられる(束の形は変えずに、鍵の置き場だけを替える)。**どちらにするかはオーナーが決める**(§6)。

### 2.3 大きさ
- 追加の章の文言は、1 言語あたり 0.5〜1.6 MB の見込み(本編の L10n §6.2 と同じ桁)。5 言語と言語に依らない部分で 3〜9 MB を同梱する。字体(4.7 MB)と同じ桁で、ipa の大きさの心配は小さい。合計が 30 MB を超えたら、後から落とす形(Background Assets)を考え直す。

## 3. 本体の側(DEC-G10・G11)
### 3.1 遊ぶ場ごとの ContentDB
- 今の層の仕組み(公開 → 非公開。後の層が同じ ID を置き換え、`remove` で消す)に、3 つ目の層として追加の章を重ねる。
- 追加の章は、`start`・`mapGen`・`clock` のような 1 つしかない定義を、本編と違う値で持ちうる。本編を遊ぶときに重ねると本編が変わってしまうので、**遊ぶ場(campaign)ごとに ContentDB を作る**:
  - 本編: 公開 → 非公開。
  - 追加の章: 公開 → 非公開 → 追加の章。
- `ContentLoader.loadBundled(root:key:)` に「遊ぶ場」を渡す口を足す(`campaign: .main / .chapter2`)。追加の章の場は、権利があるときだけ作る(DEC-G9)。
- どの場の保存かは、保存の封筒の `content`(遊んでいた層の ID と版。今もある)で分かる。`chapter2` の層を含む保存は、追加の章の場で開く。権利が無い端末でその保存を読もうとしたら、「この記録は追加の章のもの」と出して開かない(保存は消さない)。
- 保存の形(`SaveEnvelope`・`WorldState`)はこのために変えない。

### 3.2 節目の枠(本編のクリアの記録)
- `SaveSlot` に `case milestone(MilestoneID)` を足す(ファイル名 `milestone-<ID>`)。`MilestoneID` は RFKernel の型付き ID。本編では 2 つ:
  - `main.mark`: 本編の途中の節目。どの時点かは非公開の側のコンテンツが決める。
  - `main.final`: 本編の最後の日(最後の場面が始まる直前の世界)。
- 書く時: コンテンツの効果 `Effect.milestone(MilestoneID)` が出た時点で、画面が自動で書く(夜明けの自動セーブと同じ流れ。`SaveBook.writeMilestone`)。同じ ID は上書き(何度クリアしても最新が残る)。
- 消さない: 「最初から」でも、ロードでも、巻き戻しでも消さない(手動の枠と同じ扱い)。
- 本編のクリアの印: `main.final` があれば「本編をクリアした」とみなす(タイトルの 1 行。§4.2)。
- 保存の形への影響: `SaveSlot` の case が 1 つ増えるだけで、今の保存はそのまま読める。凍らせた見本も変わらない。アプリの switch(`check-app-switches.py`)は網羅を直す。

### 3.3 追加の章の始め方
- タイトルの「追加の章」(権利あり・`main.final` あり・追加の章へつながる終わり方): `main.final` の世界を読み、追加の章の場の ContentDB で、`ChapterBridge.begin(from:content:)` を当てて新しい世界を作る。
  - 何を引き継ぎ、何を追加の章の定義から作り直すかは、コンテンツの表で決める(巻き戻しの `MemoryCarry` と同じ作り。人・在庫・来歴・知った事実・ノート・記憶・地図・時計などの集まりごとに「引き継ぐ / 作り直す」を選ぶ)。引き継ぐ人と引き継ぐ在庫は、コンテンツの事実で決まる。中身は非公開のデータ(U14)が決める。
- 追加の章へつながらない終わり方をした人: タイトルの「追加の章」は、`main.mark` の世界を**本編の場で**読み、そこから本編を遊び直す(非公開の側の既定)。その後、本編の最後の日に着けば `main.final` が書き直され、追加の章を始められる。どの終わり方でも、本編の保存(自動・手動・中断)はそのまま残す。
- どの終わり方が追加の章へつながるかは、コンテンツの事実で決める(本体は終わり方の数も名前も知らない)。
- 追加の章の中の保存は、本編と同じ規則(D-save §7)。夜明けの自動・手動・中断。巻き戻しは追加の章の夜明けの中だけ。

## 4. 確かめ
### 4.1 テスト
- 本体: 遊ぶ場ごとの ContentDB(本編の場に追加の章の定義が混ざらない・追加の章の場は上に重なる)。節目の枠の書き方と消えなさ。`ChapterBridge` の引き継ぎの表。権利の無い場で `chapter2` の層を含む保存を開かない。
- アプリ(macOS の CI): 権利の確かめ(StoreKit のテスト用の設定ファイル `.storekit` で、買う・復元・払い戻し・家族共有)。
- 静的: 本編の終わりの場面とクレジットの文言に、購入・値段・追加の章の文言 ID(`ui.store.*`・`ui.chapter2.*`)が無い(非公開の側の TEST-E1)。
- ボット: 本編をすべての終わり方でクリアし、権利の無いまま最後の場面・クレジット・タイトルまで、購入の画面が一度も出ない(非公開の側の TEST-E3)。
- CI: ipa に追加の章の平文が無い。

### 4.2 タイトルの 1 行
- 出す条件: `main.final` がある(本編をクリアした)。権利が無ければ「追加の章」の 1 行から設定の購入の所へ。権利があれば始める(§3.3)。本編をクリアしていない人には出さない(「本編を終えると始められる」は、設定の購入の所の説明にだけ書く)。
