# L-10a どの画面にもある設定のボタン(Codex への説明書)

書いた人: architect(統合担当)。実装: Codex(relay:codex-impl)。土台: 統合の枝 `integration-c` の先頭。
オーナーの決定(2026-10-02): 設定のボタンを、どの画面にも常に出す。PT(人が遊ぶ試し)に出す前に要る。
L-10 のうち「ボタンと設定の開き方」だけをここで作る。言語の一覧(`AppLanguage`・言語の読み替え・`setLanguage`)は L-03 の後の L-10b に残す(設定の中に言語の節を置く場所だけ空けておく)。

## 1. 置き方
- ボタンは画面ごとに置かない。アプリの一番上の層に 1 つだけ置く。SwiftUI のシートは画面の木の上に重なるので、木の根に重ねたボタンはシートに隠れる。だから、**ボタンだけを載せた透明の窓**(`UIWindow`。`windowLevel` は通常より上。ボタンの外の押下は下の窓へ通す: `hitTest` でボタンの外なら `nil` を返す)を作り、そこに `UIHostingController` で SwiftUI のボタンを置く。シーン(`UIWindowScene`)ごとに 1 つ。
- タブを替えても、頁を開いても、下からの札(`InkCard`)が上がっても、決断の帯・序・ゲームオーバー・読み込みの失敗の画面・シートが出ても、同じ所に見えている。
- 場所: 右上の安全な領域の内側。押せる範囲は 44×44pt、周りに 4pt の余白で、**右上の 52×52pt を「設定の角」**とする。
- 見た目: 歯車(SF Symbols の `gearshape`)。文字は持たない。地図の上でも読めるよう、暗い半透明の丸の上に描く(色は `InkColor` から)。読み上げのラベルは「設定を開く」/ 開いているときは「設定を閉じる」(今の決まりの `Text("…")` のリテラル。L-11 で表へ移す)。`accessibilityIdentifier` は `settingsButton`(開閉で変えない)。

## 2. 開き方
- 押すと設定(今の `SettingsView`)が、地図の下半分に出る(中ほどの高さの札。今の `inkCard` の作りを使ってよい。地図は上に見えたまま)。同じボタンをもう一度押すと閉じる。設定の中から開いた札(購入など)も一緒に閉じる。
- 設定の一番上に、言語の節の場所を空けておく(この作業では中身を作らない。L-10b)。
- ゲームの側から設定を開くことはしない。
- **時計**: 設定が開いている間、アプリは本体の時計(`GameStore` の `tick`・`advance`)を呼ばない。ゲームの時間は止まる。閉じたら、止めていた間の実時間を進めない(再開した時点から数える)。
- 設定はゲームのコマンドではない(本体には何も送らない)。

## 3. 今あるボタンの整理
- タイトルの設定のボタン(S-02 の `titleSettingsButton`)と、拠点のタブの「設定」のボタンは消す(角のボタン 1 つにする)。画面の写真のスクリプト(`ReForgeUITests/ScreenSnapshotTests.swift`)が `titleSettingsButton` を押して設定を撮っているなら、`settingsButton` に替える。
- 各画面は、右上の 52×52pt に押せる物や文字を置かない: 状態の帯・タブの頁の見出し・パネルの見出し・下からの札の右上を見直し、重なる物があれば左へ寄せる(帯は右に 52pt を空ける)。

## 4. 確かめ(TEST-L16)
- 画面の写真のジョブ(`docs/briefs/screen-snapshots.md`)の、撮る全部の画面(地図・下からの札・設計・拠点・仲間・研究・ゲームオーバー・設定・タイトル・序・ノート・決断の帯・読み込みの失敗。撮れていない画面は撮れる所まで)× 5 言語で、`settingsButton` が
  1. ある、2. 押せる(`isHittable`)、3. 窓の中の右上の 52×52pt にある、4. ほかの押せる要素の枠と重ならない。
  設定を開いた状態では、同じ所のボタンで閉じられる。1 つでも外れたら UI テストを失敗にする(`screens/report.json` に画面・言語・理由)。
- アプリの単体テスト(`ReForgeTests`): 設定が開いている間は `GameStore` の時計が進まない(開く前と閉じた後のゲームの時刻を比べる)。

## 受け入れ
- macOS の CI(ci/integration)でアプリのビルド・単体テスト・画面の写真のジョブが通る(統合担当が回す)。
- 静的: `check-app-switches.py`・`check-app-names.py`・`gen-xcstrings.py --check`(カタログを作り直す)・`check-public-spoilers.py`。
- 本体(ReForgeCore)は触らない。
