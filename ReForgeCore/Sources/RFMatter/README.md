# RFMatter — 物質・命名・レシピの純度・連結の工程

他のターゲットに依存しない葉。状態は値型(Codable・Hashable・Sendable)で、計算は決定的(純度は万分率の整数)。
表示名は持たない。命名は名前の部品(語の ID の並び)を返し、文字列化は `NameRendering` を実装する側(認識の層)が行う。

- 入口: `ProcessChain.run(steps, input:, rules: .r1)` → `ChainResult`(物・名前の部品・硬さ・粘り・副産物・所見 ID・使った材料・段ごとの記録)
- 1 段ずつ: `ProcessChain.advance` / `ProcessChain.finish`(設計画面の途中の見込み用)
- 規則の表: `RuleBook.r1`(`RuleBookR1.swift`)。モジュールは表に ID と規則を足すだけで増やせる
- 保存: `MatterCoding.encoder()`(キーを並べ替える)で書く。enum の連想値・ID の保存キーは明示してあり、テスト `testGoldenJSON` が固定の JSON 文字列で退行を見る

## 原作・設計書(order.md)からの差分と理由

仕様の正本(order.md §5.4・§5.6)への反映はリーダーが行う。ここは実装側の一覧。

| # | 差分 | 理由 |
|---|---|---|
| 1 | 木炭炉(`charcoal_smelt`)に石灰石のフラックスを持たせ、加算を **+25** にした(原作はフラックスなし。order.md は `basic_smelt` の +18 を想定) | 木炭炉の base 55・W 0.3 に +18 では、前処理を全部しても 55×0.7 + 85×0.3 + 18 = 82% が上限で、精(85%)に届かない。+25 なら「砕く→洗う→混ぜる→木炭炉」がそろったときだけ届く(鉱石 20〜60%)。`RecipeOverride.r1` |
| 2 | **叩き重ね**のレシピ `r1_fold`(base 94・W 0.5)と規則を足した。熱し直した板をもう一度叩くと純度が上がる。2 回まで | 精鉄板への道が石灰の 1 本だけだったため(レビュー指摘)。石灰を使わず、木炭と手間を多く使う 2 本目の道「砕く→洗う→炉→叩く→(熱し直す→叩く)×2」を作った。露頭 20〜35% で 85.72〜85.85%、洗いを抜くと 83.88〜84.33% で届かない。`RecipeBook.r1Additions` |
| 3 | 露頭の鉱石を **20〜35%** とする(order.md §5.6 は「30% 前後」) | 木炭炉 1 回の最低が 47.5% で粗鉄塊・粗鉄板が作れなかった。20% で 44.5%(粗鉄塊)、35% で 49%(鉄塊)になり「粗鉄塊〜鉄塊の境目」に合う。規則と式は変えていない。`R1Ore.outcrop` |
| 4 | 工程の中では、燃料・水の純度を平均に入れない(物 1 つの純度だけで式を当てる) | 原作 `Recipe.Execute` はフラックス以外の全入力(燃料・水を含む)の平均を取るが、燃料の純度が鉄の純度を動かすのは工程の推理を濁す。`Recipe.execute` 自体は原作どおり。合金など入力を混ぜたい段は `applyRecipeWithInputs` を使う |
| 5 | 洗い樋は、混ぜてあった石灰を流す(所見 `wash.flux_washed_away`) | 石灰の粉を混ぜてから水ですすげば流れるのが自然で、「混ぜ物は熱する前ね」だけでは足りない順番の手がかりになる |
| 6 | 名前の語順は「純度の段 → 剛柔 → 物質 → 形」(例: 精剛鉄板)。急冷しない板はすべて柔 | order.md の R1 の名前一覧(鉄板・精鉄板・剛鉄板・柔鉄板)は剛柔の無い板を含むが、§5.4 の規則では叩いた板は必ず剛か柔になる。部品は全部返すので、図鑑で剛柔や純度の段を省くかは認識の層が決める |
| 7 | 剛は「叩いた後の急冷」だけ。叩いていない塊を冷やしても硬くならない(所見 `quench.unworked_not_hardened`)。冷やした後に叩くと割れるのは同じ | §5.4 の規則のとおり。game-design.md §2 の「冷却 → 成形 = 柔鉄板」は採らない |
| 8 | 炉で鉄を熱し直すと急冷の硬さが抜ける(焼きなまし)。叩いた後は冷めかけていて、もう一度叩くには熱し直しが要る(所見 `hammer.too_cool`) | 叩き重ねに木炭と手間がかかる形にするため |
| 9 | 混ぜ鉢に石灰石以外(または石灰石と別の物)を入れても抱えない(所見 `mix.unknown_additive`) | 黙って抱えると後の段で意図しない効きが出る |
| 10 | 鉱石の名前に形を残す(赤鉄鉱 + 塊/粉)。原作は鉱石の固有名に形を付けない | R1 では塊か粉かが工程の鍵 |
| 11 | 温度で名前が変わる物質(溶融ガラス・氷・水蒸気)は R2。99.999% は万分率で表せないので、超高純度アルミの段は 100.00% | 万分率の整数にしたため |
| 12 | 18 特性の 17・18 番目は `traitR3a`・`traitR3b` という抽象名。R1 では既定値のまま | 公開リポジトリのため |
| 13 | 硬さ・粘りは 0〜100 の指数で R1 の仮値(規則の表 `metrics`)。純度の効き(`PurityMath.effect`)は掛けていない | 対数の末位が端末でずれうるので、決定的な計算に混ぜない |
| 14 | 原作の `ProcessingChain`(段数で量が増えるだけ)は移植せず、連結の工程は設計書から新しく作った | 原作に順番で性質が変わるコードが無い |

## 到達の数え上げ(鉱石 30%、テスト `ReachabilityTests` が出力する)

| 並びの範囲 | 並びの数 | 精鉄板 | 剛鉄板 | 無作為 8 回で精鉄板 |
|---|---|---|---|---|
| 各種類 1 回まで(炉は燃料 2 通り) | 3,587 | 6(0.17%)。効果のない段を除くと 2 | 193(5.38%) | 1.33% |
| 繰り返しあり・長さ 6 まで | 137,256 | 35(0.03%) | 3,737(2.72%) | 0.20% |
| 繰り返しあり・長さ 8 まで | 6,725,600 | 10,891(0.16%) | 341,828(5.08%) | 1.29% |

本質的に違う道(効果のある段だけで、どの 1 段を抜いても届かない並び)は 5 本、入れ替えても効きが同じ段の違いをまとめると 4 通り:
石灰の道(砕→洗→混→熱→叩)、叩き重ねの道(砕→洗→熱→叩→熱→叩→熱→叩)、石灰と叩き重ね(砕→混→熱→叩→熱→叩 / 混→熱→叩→熱→叩→熱→叩)。
