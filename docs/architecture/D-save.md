# D. 保存の形式・セーブ地点・巻き戻し

正本のコード: `RFSave/SaveCodec.swift`・`RFFailure/Failure.swift`。

## 1. 形式
- 1 ファイル = `SaveEnvelope`(JSON・キーは昇順): `format`("reforge.save")・`schemaVersion`(世界状態の形の版)・`content`(遊んでいたコンテンツの層の id と版)・`slot`・`world`(`WorldState` 丸ごと)。
- 世界状態は ID と整数だけ(B §1)。名前・文章は入らないので、コンテンツの文を直しても保存は壊れない。
- 本体はファイルに触らない。置き場はアプリが `SaveStorage`(書く・読む・消す・一覧)を FileManager で実装する(テストは辞書)。書くときは一時ファイル → 置き換え(途中で落ちても前の保存が残る)。
- b7 の保存(`SaveFile` 版 1)は読まない(旧版の互換は除外候補。b7 の利用者はオーナーだけ)。

## 2. 保存の場所(スロット)
| スロット | いつ書く | 何に使う |
|---|---|---|
| `resume` | アプリが背面に回る・閉じる・日没・夜明け・決断を出したとき(画面側が呼ぶ) | 「つづきから」。時計は止めた状態で戻す |
| `dawn(day)` | 夜明けごと(自動)。直近 3 日ぶん残す(`SavePolicy.keepDawns`) | 巻き戻しの戻り先(最新)と「セーブ地点からロード」 |
| `manual(index)` | プレイヤーが拠点の画面から(確認は出さない。上書きは戻せないので 3 枠) | 「セーブ地点からロード」 |

画面の途中の状態(置くモードの照準・設計画面の下書き)は世界状態に入れない。`resume` と同じ時に画面側の小さな JSON として別に書く(読めなくても遊べる)。

## 3. ゲームオーバーの 4 択と、巻き戻しの持ち越し
失敗はコンテンツの失敗の規則(`FailureRuleDef`。期限も値で判定)が成り立ったとき(`run.outcome = .failed`)。画面は 4 つを同じ重さで並べる。

| 選択 | 作り方 |
|---|---|
| 最初から | `WorldFactory.newWorld(seed: 新しい seed)`。何も持ち越さない |
| 記憶を持って巻き戻す | `MemoryCarry.rewind(failed:, dawn: 最新の dawn, content:)`。最新の夜明けがすぐ失敗に落ちる場合のため、直近 3 日の夜明けから選べる |
| 失って続ける | 失敗した世界に、コンテンツの `RewindDef.lossEffects`(誰かが去る・物を失う…)を適用し、失敗の原因の値を戻して続ける。失ったものは来歴に残る |
| セーブ地点からロード | `dawn` か `manual` を読む。持ち越しなし |

記憶を持って巻き戻すときの分け方(MECH-04・REQ-S6):

| 戻す(夜明けのまま) | 残す(失敗した世界から写す) |
|---|---|
| 在庫・ライン・置いた物・建造物・運搬 | 知った事実(コンテンツの `FactDef.scope` が memory のもの。timeline のものは消える) |
| 仲間の生死・位置・体・配属 | 地図の既知・見つけた POI と鉱脈・図鑑の影 |
| 時計・数値・出来事の進み・範囲の効果 | 実験ノート(試作・所見・出典つきの書き留め・聞いたヒント) |
| 研究の進み・解禁 | 関係の点とランク(割合は巻き戻しの定義のデータが書く) |
| 来歴(夜明けまで) | 持ち越すと定義された記憶(記憶の定義のデータが決める) |
| | 前の周回の記録の写し(どの印の来歴を写すかは巻き戻しの定義のデータが決める) |

- 周回の番号(`run.index`)を 1 つ増やす。実体の ID と来歴の番号は失敗した世界の続きから振る(前の周回の記録と番号が重ならない)。
- 前の周回の記録は、条件(`Condition.runAtLeast`・来歴の問い合わせ `currentRunOnly: false`)で引ける。何に使うかはデータが決める。

## 4. 版と移行
- 世界状態の形を変えたら、`SaveCodec.schemaVersion` を 1 上げ、`SaveCodec.migrations` に「前の版の JSON の木(`Value`)を次の版の木に書き換える」移行を 1 つ足す。古い struct を残さなくてよい。
- 読むときは版を 1 つずつ上げる。移行が無い版・新しすぎる版は読まない(壊れた状態で始めない。画面は「この保存は読めない」と 1 行出し、他のスロットを勧める)。
- コンテンツの ID を付け替えたら、コンテンツ側に付け替えの表を置き、読み込み後に世界状態の ID を写し替える(U3・U12 で形を決める。R1 のリリースまでは不要)。
- 最初のリリース(R1 を外に出す)までは版 1 のまま形を変えてよい。リリース後は必ず移行を足す。

## 5. 受け入れテスト(U12)
- 封筒の往復(書いて読んで同じ)。移行の連鎖・新しすぎる版・保存でないファイル。
- 巻き戻しの持ち越し(上の表の各行)。番号が重ならない。timeline の事実は消える。
- 4 択のそれぞれで、続けられる世界になる(`run.isActive`)。
- 中断(TEST-R1-08): 置くモード・試作の途中・会話の途中で `resume` を書き、読んで続きから(時計は止まっていた)。

## 6. U12 の実装で決まったこと(b59cac6)
- 封筒に `summary`(seed・日・相・周回・巻き戻し回数・進行中か)。一覧の表示と「同じ走行の夜明けか」の判定に使う。
- 画面の途中の状態は `SaveSlot.screen`(ファイル `resume-ui.json`)に生の Data で置く。
- 保存の JSON は自前の正準の書き出し(`CanonicalJSON`。Set と非文字列キーの辞書をソート、キーは UTF-8 順)でバイト列を固定する。固定の JSON は `Tests/RFSaveTests/Fixtures/save-v1.json`。リリース前は形が変わるとテストを飛ばし、作り直し方(`REFORGE_UPDATE_SAVE_FIXTURES=1`)を出す。リリース後は失敗にする。
- 失って続ける: `RewindDef.lossEffects` があればそれだけ。無ければ既定(関係の点が最も低い一員 1 人が去る・拠点の蓄えの唯一品でない物の 500‰ を失う)と、成り立っていた失敗の規則の `onContinue`。適用しても失敗の規則が成り立つなら選べない。
- 前の周回の記録の写しには、印の付いた記録と失敗の記録に加えて、持ち越した事実・ノート・記憶が指す記録を残す(`RunState.pastRecord` で引ける)。巻き戻しの後に付ける記憶は、巻き戻しの定義のデータが決める。
- 保存の書き換えは `Recovery.perform` の中: 最初から = 夜明けと続きを消す(手動は残す)/ 巻き戻し = その夜明けを巻き戻した世界で上書きし、先の夜明けを消す / ロード = 先の夜明けを消す。
- 画面へのつなぎ(統合担当が GameHost に入れる): `SaveBook.autosaveDawn`(出来事に dawn)・`writeResume`(背面に回る時)・`Recovery.choices / perform` → `GameHost.replace`。

## 7. 手動の枠と自動の枠(オーナーの決定 2026-10-02。統合担当の見直し)
オーナーは「セーブの枠を手動用と自動用に分ける」と決めた。今の `SaveSlot` は、すでに次の 3 種に分かれているので、**保存の形(`SaveSlot`・ファイル名・`SaveEnvelope`)は変えない**。凍らせた見本(`Fixtures/save-v1-dev-*.json`)はそのまま読める。足りないのは、画面での見分け方と、タイトルからの読み込みだけ(作業の単位 S-04)。

| 種類 | スロット | 書く時 | 数 | 消える時 |
|---|---|---|---|---|
| 中断 | `resume` + `screen` | 背面に回る・閉じる・日没・夜明け・決断・4 択の後・ロードの後 | 1 | 最初からを選んだとき(書き直す) |
| 自動 | `dawn(day)` | 夜明けごと(進行中の世界だけ) | 同じ走行の直近 3 日(`SavePolicy.keepDawns`) | 4 日より古い・別の走行・時間軸を捨てたとき(ロード・巻き戻し・最初から)より先の日 |
| 手動 | `manual(index)` | プレイヤーが拠点の画面の「記録」で選んだ枠に(確認なしで上書き) | 3(`SavePolicy.manualSlots`。オーナーの決定 2026-10-02) | 消さない(最初からを選んでも残す) |

### 7.1 ゲームオーバーの 4 択
| 選択 | 読む枠 | 枠の書き換え |
|---|---|---|
| 最初から | なし | 自動と中断を消し、新しい世界の 1 日目の夜明けと中断を書く。手動は残す(`SaveBook.startNew`) |
| 記憶を持って巻き戻す | **自動の枠だけ**(同じ走行・失敗した日以前の夜明け。既定は最新、残りから選べる) | 戻った夜明けを巻き戻した世界で上書きし、それより先の夜明けを消す。中断を書く |
| 失って続ける | なし(失敗した世界をそのまま直す) | 中断だけ書く。**自動の枠はそのまま残す**(どれも失敗より前の同じ時間軸なので、後でそこへ巻き戻すと「失ったこと」も無かったことになる。それは巻き戻しの意味どおり) |
| セーブから読む | **自動と手動の両方**(進行中の世界のものだけ。読めない枠は理由つきで一覧に残し、黙って落とさない) | 読んだ世界の時間軸に切り替える(別の走行と先の日の夜明けを消す)。中断を書く。手動は消さない |

- 巻き戻しに手動の枠を使わない理由: 記憶の持ち越し(§3 の表)は「夜明けの世界」を前提に決めてある。手動の枠は昼の途中や別の走行のこともあり、戻す物と残す物の境が決まらない。手動の枠へ戻りたいときは「セーブから読む」(持ち越しなし)を使う。

### 7.2 つづきから
- タイトルの「つづきから」は、**中断の枠(`resume`)だけ**を読む(画面の途中の状態 `screen` が読めればそれも)。中断の枠は上の表の時にいつも書き直すので、3 種の中でいちばん新しい。自動・手動を「いちばん新しいもの」として比べることはしない(本体は壁時計を読まないので、新しさを比べる手段が無い。比べなくても中断がいちばん新しい)。
- 中断の枠が無い・読めない(版が新しすぎる・壊れた)とき: 「つづきから」は出さない。代わりにタイトルに「セーブから読む」を出し(自動か手動が 1 つでもあれば)、4 択の「セーブから読む」と同じ一覧を開く(作業の単位 S-04。今はタイトルからは読めない)。

### 7.3 寝る(夜を飛ばす)と夜の作業
- 寝た後の夜明けで、自動セーブは**走る**(画面が相の変わり目を見て `autosaveDawn` と中断を書く。夜の作業で夜明けに着いたときも同じ)。
- 寝る前に自動の枠は**書かない**。日没で中断の枠は書いている(落ちても日没から続く)。巻き戻しの戻り先は夜明けだけにする(夜の前に戻せると、夜の危険を何度でも選び直せてしまう。夜の前に残したい人は手動の枠を使う。手動の記録は夜でも書ける)。
- 寝ると夜の作業の違いは、保存については無い。どちらも夜明けに着いた時点で自動セーブが走り、途中では中断の枠だけが(背面に回ったときに)書かれる。夜の作業の途中で失敗したときの巻き戻し先は、その夜の前の夜明け。

### 7.4 画面での見分け方(作業の単位 S-04)
- 拠点の「記録」と、4 択・タイトルの「セーブから読む」の一覧は、**自動と手動の 2 つの節に分けて**出す(見出し: 自動 = 夜明けの記録、手動 = 自分の記録)。自動の行は「N 日目の夜明け」、手動の行は「手動 N」と、その中身の日と相(「N 日目の昼」など)。空いた手動の枠は「空き」。
- 文言は今は `Text("…")`(カタログのキー)。L-11 で `ui.save.*` の ID の文言の表に移す(多言語)。数は引数にする(断片をつながない)。

### 7.5 確かめ(S-04 のテスト)
- 本体: 4 択のそれぞれの後の枠の一覧(上の表)。失って続けた後も自動の枠が残り、その後の夜明けで新しい自動の枠が足される。寝る → 夜明けの後に自動の枠が 1 つ増える。手動の枠は最初からを選んでも残る。
- 凍らせた見本と `save-v1.json` は変わらない(形を変えないので)。

## 8. 購入の権利と保存(オーナーの決定 2026-10-02。G §1.2・§1.4)
- 購入の権利(本編の解放 `reforge.fullgame`・追加の章 `reforge.chapter2`)は**保存に入れない**。保存の形は変えない。権利は端末の StoreKit の署名付きの記録から毎回作る(オフラインで判定)。
- 本編の区切り(`trialGate`)を越えた保存も、権利の無い端末で読める。読んだ世界で区切りの条件が成り立っていれば、本体の門が働く(既定の `fence` は研究の始めと挙げた出来事だけを待たせる。`freeze` は世界ごと止める)。保存は消さない。
- 門が働いている間も、中断・自動・手動の保存は書ける。待たせた出来事の列(`WorldState.trial`。新しい任意の欄で、無い保存は空として読む)は保存に入り、権利を得たら積んだ順に起きる。体験版の保存は製品版でそのまま続く。
- 巻き戻し・失って続ける・最初からも、権利の有無で変えない(門は世界の条件だけを見る)。
